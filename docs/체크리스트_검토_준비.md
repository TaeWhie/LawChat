# 체크리스트 검토 준비 자료

체크리스트를 다시 살펴보기 위해, 프로젝트 내 **체크리스트 관련 문서·코드·API·설정**을 한곳에 모았습니다.  
(코딩 없이 정리만 한 준비 문서입니다.)

**▶ 작업 범위: API 위주.** 프론트엔드(Streamlit, app_chatbot.py UI 등)는 신경 쓰지 않습니다.

---

## 1. 프로젝트에서 "체크리스트"가 쓰이는 두 가지 의미

| 구분 | 의미 | API/백엔드 관점에서 관련 위치 |
|------|------|------------------------------|
| **상담 플로우의 체크리스트** | 사용자 상황 확인용 **네/아니요/모르겠음** 질문 목록. 이슈 분류 후 생성 → 사용자 답변 → 결론 생성으로 이어짐. | `rag/pipeline.py` (step2_checklist), **POST /api/v1/chat/checklist**, **POST /api/v1/chat/invoke** (phase=checklist), `config.py`, 프롬프트 |
| **작업·검증용 체크리스트** | 법령 API 도입, API 확인, 코드 개선 시 **확인할 항목 목록**. | `checklist_law_api_migration.md`, `verification_checklist.md`, `REVIEW_CODE_AND_PRODUCT.md` |

아래는 두 가지를 구분해서 정리했으며, **API·백엔드**에 초점을 둡니다.

---

## 2. 상담 플로우의 체크리스트 (기능)

### 2.1 역할·플로우

- **역할**: 이슈(예: 퇴직금)에 대해 **사실/요건을 확인하는 질문**을 RAG 기반으로 생성.
- **플로우**:  
  `상황 입력` → `이슈 분류` → **[체크리스트 생성]** → 사용자가 각 질문에 **네/아니요/모르겠음** 선택 → (최대 3라운드 반복 가능) → **결론 생성**.

- 출처: `docs/PRODUCT_DESIGN.md` (진단적 상담 흐름). *(플로우 이해용, UI는 작업 범위 아님.)*

### 2.2 UI (참고만 — 작업 범위 아님)

- 프론트엔드는 신경 쓰지 않음. 필요 시 참고: `app_chatbot.py` (체크리스트 버튼, 진행률, 세션 키 `cb_checklist` 등).

### 2.3 API ← 작업 중심

- **POST /api/v1/chat/checklist**  
  - 용도: 이슈·상황·기존 Q&A 기반으로 체크리스트(질문 목록) 생성.  
  - 요청: `issue`, `situation` 필수. `all_qa`, `round`, `previous_rag_results` 등 선택.  
  - 응답: `checklist`(배열, 항목은 `item`, `question`), `rag_results`, `should_continue`, `continuation_reason` 등.

- **POST /api/v1/chat/invoke**  
  - 한 번에 상담 플로우(이슈 분류 → 체크리스트 → 결론 등) 수행.  
  - 응답 `phase`가 `"checklist"`일 때 `checklist`, `checklist_rag_results` 포함.

- 상세: `docs/API_사용방법_전체.md` §10, §invoke 응답 필드.

### 2.4 파이프라인 (rag/pipeline.py)

- **함수**: `step2_checklist(...)`  
  - 입력: `issue`, `filtered_provisions_text`, `remaining_articles`, `qa_list` 등.  
  - 동작: `remaining_articles` 우선 사용 → 없으면 이슈별/전체 RAG 검색 → 컨텍스트로 LLM에 질문 생성.  
  - **재시도**: 컨텍스트가 없으면 확장 검색·이슈명만 검색 등 재시도 전략.  
  - 반환: `{"checklist": [...], "rag_results": [...], "error": "...", "debug_info": {...}}`.

- **체크리스트 0개 시 재시도** (SCENARIO_VERIFICATION.md):  
  첫 호출에서 체크리스트 0개이고 `max_tokens`가 6000 이상 또는 None이면, `max_tokens=4096`으로 한 번 더 호출.

### 2.5 설정 (config.py)

| 상수 | 기본값 | 설명 |
|------|--------|------|
| `CHECKLIST_MAX_ITEMS` | 7 | 한 차수당 최대 질문 개수 |
| `CHECKLIST_CONTEXT_MAX_LENGTH` | 5000 | 체크리스트용 RAG 컨텍스트 글자 수 |
| `CHECKLIST_MAX_TOKENS` | 4096 | 체크리스트 LLM 응답 상한 |
| `CHECKLIST_MAX_ARTICLES` | 12 | 체크리스트 생성 시 참조 최대 조문 수 |
| `RAG_FILTER_TOP_K` | 20 | 관련도 필터 후 유지 개수(체크리스트에 더 많은 조문 반영) |

### 2.6 프롬프트 (API / prompts)

- `system_checklist`, `user_checklist`: 1차 체크리스트 생성.  
  - user 플레이스홀더: `issue`, `rag_context`, `filtered_provisions`, `already_block`, `tail` 등.
- `system_checklist_continuation`, `user_checklist_continuation`: 추가 질문(2차 이상).  
  - user 플레이스홀더: `issue`, `qa_text`, `rag_context`.
- 조회: **GET /api/v1/prompts** → `prompts`, `placeholders` 참고.

### 2.7 개선 제안 (문서만)

- `docs/SCENARIO_IMPROVEMENTS.md`: 이슈별 필수 확인 사항 정의 후 체크리스트에 반영, 해고 예고 기간·서면 통지·괴롭힘 유형·계약 기간 등 구체적 질문 분리.
- `docs/ARCHITECTURAL_IMPROVEMENTS.md`: Step 2 체크리스트 생성 실패 시 재시도 전략(확장 검색, 이슈명만 검색, 여전히 없으면 에러 반환).

## 3. 작업·검증용 체크리스트 (문서)

### 3.1 법령 API 도입 시 체크리스트

- **파일**: `docs/checklist_law_api_migration.md`
- **목적**: 법령 원문을 현행법령 API에서 가져오도록 전환할 때 확인·수정할 위치 정리.
- **섹션**: 설정·환경, 데이터 로드 경로, 분류·메타데이터(JSON) 연동, 벡터 스토어, API 사용하는 쪽, 앱·그래프·파이프라인, 스크립트·테스트, 운영·배포, 한 줄 요약.

### 3.2 API 확인 완료 체크리스트

- **파일**: `docs/verification_checklist.md`
- **목적**: 법령·해석·판례·위원회, 지능형 법령정보지식베이스 등 **API 항목별 확인 상태** 정리.
- **내용**: 체크 항목 vs 확인 완료 항목, target 값, 다음 단계(실제 API 호출 테스트, JSON 응답 구조 확인 등).

### 3.3 코드/기획 요약 체크리스트

- **파일**: `docs/REVIEW_CODE_AND_PRODUCT.md` §3 요약 체크리스트
- **목적**: 단계적 개선 시 참고용. 로깅, api_cache 예외 처리, app.py 분리, 단위 테스트, 기획(에러 메시지, 가이드), 문서 정리 등 우선순위(높음/중/낮음) 표 기재.

## 5. 다음 단계 제안 (검토 후, API 위주)

- **상담 체크리스트 (API·백엔드)**:  
  - **API**: `/chat/checklist`, `/chat/invoke` 요청/응답 스키마, 에러 코드, `prompt_overrides` 지원 여부 검토.  
  - **파이프라인**: `step2_checklist` 재시도 전략, 최대 항목/라운드 상수, 프롬프트 변경.  
  - **설정**: `config.py`의 CHECKLIST_*, RAG 관련 값 조정.
- **작업용 체크리스트**:  
  - 법령 API 도입 → `checklist_law_api_migration.md` 기준 백엔드·API 변경만 진행.  
  - API 확인 → `verification_checklist.md` 다음 단계(실제 호출 테스트 등).  
  - 코드 개선 → `REVIEW_CODE_AND_PRODUCT.md` §3에서 API·서버 관련 항목만 선택.

이 문서는 **검토 준비**만을 위한 것이며, 실제 수정은 검토 후 **API 위주**로 진행하시면 됩니다.
